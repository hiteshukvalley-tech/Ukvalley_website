# Ukvalley Technologies — website + admin panel

Next.js 16 (App Router) site with a MongoDB-backed admin panel at `/admin`.

## Local development

```bash
npm install
cp .env.example .env.local   # fill in the values
npm run dev                  # http://localhost:3000
```

`npm run dev` compiles each page the first time it is opened, so the first
visit to a page is slow. To judge real speed, use a production build:
`npm run build && npm start`.

## Deploy to Render

The service is defined in `render.yaml` (a Render Blueprint): a Node web
service that runs `npm ci && npm run build`, then `npm start`.

1. **Push the code to GitHub.** `.gitignore` already keeps out `.env*` (except
   `.env.example`), `.next`, `.next-test`, `.shots`, `*.zip` and the local
   HTTPS certificates.
2. **Create the service:** Render dashboard → **New → Blueprint** → connect
   the `Ukvalley_website` repository → Render reads `render.yaml`.
3. **Fill in the secrets** Render asks for:

   | Key | Value |
   |---|---|
   | `ADMIN_EMAIL` | owner login email |
   | `ADMIN_PASSWORD` | a long, unique passphrase |
   | `MONGODB_URI` | Atlas connection string |

   `AUTH_SECRET` is generated by Render; `MONGODB_DB` is preset to `ukvalley`
   and `NODE_VERSION` to 22. Change any of them later under the service's
   **Environment** tab; saving triggers a redeploy.
4. **MongoDB Atlas → Network Access:** allow the service's outbound IPs
   (Render service → **Connect → Outbound**), or `0.0.0.0/0`.
5. **Deploy** (automatic on every push to `main`), then open
   `/admin/login`, sign in as the owner and check *Admin → Dashboard* shows
   "Database: Connected". If the database is new, run
   *Admin → Migration → Import all* once.
6. **Domain:** add `ukvalley.com` and `www.ukvalley.com` under the service's
   **Settings → Custom Domains** and create the DNS records Render shows. The
   site's canonical URLs, sitemap and Open Graph tags already use
   `https://ukvalley.com`.

### Platform notes

- Render runs one long-lived Node server, so the MongoDB connection pool and
  the in-memory login / contact-form rate limits are shared by every request.
  With more than one instance, each keeps its own rate-limit counters.
- Media files are stored in MongoDB (GridFS), not on Render's disk, which is
  wiped on every deploy. Uploads go one file per request, max 4 MB each.
- The free plan sleeps after 15 minutes without traffic and has 512 MB RAM;
  `render.yaml` uses the always-on Starter plan.

## QA

Run the suites against a production build that uses a scratch database:

```bash
NEXT_DIST_DIR=.next-test MONGODB_DB=ukvalley_qa npx next build
NEXT_DIST_DIR=.next-test MONGODB_DB=ukvalley_qa npx next start -p 3100
node scripts/qa/01-access-and-pages.mjs   # …02, 03, 04, 05 (home page editor)
```
